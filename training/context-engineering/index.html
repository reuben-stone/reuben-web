Context engineering & memory

Controlling what the model sees at each step - context selection as architecture, token budgets as engineering constraints, and memory patterns that serve the task.

01

Context is architecture, not a prompt trick

The engineering question isn't "what should the prompt say" but what evidence and state should enter the context at this step?

Context selection determines model performance more than prompt wording. You can spend hours refining an instruction, but if the model is reasoning over the wrong evidence, the instruction doesn't matter.

A larger context window increases capacity but doesn't solve relevance, cost, latency, or deciding what matters now. Capacity is not the same as curation.

Concrete Artemis connection

ContextPacket makes context selection explicit. Workflow objective, repository evidence, previous tool results, current state, available tools and constraints are deliberately chosen per step. Context selection is part of the architecture, not an afterthought.
02

Token budgets as engineering constraints

Tokens are a finite resource, not an infinite dumping ground. Every token included has a cost: money, latency, and attention.

Budget allocation means making explicit decisions: how much for system instructions, how much for evidence, how much for history, how much for the current task.

The cost of including irrelevant context isn't just tokens - it's attention dilution, increased latency, and higher costs. When a model receives too much context, it can miss or de-prioritise relevant information buried among irrelevant content.

Concrete Artemis connection

Context is selected for the current task rather than blindly accumulated. The budget forces decisions about what matters right now. Without a budget, the default is to include everything. With a budget, the system must rank and select.
03

What to include vs what to retrieve

Not all context belongs in every step. The decision of include vs retrieve vs omit is an architectural choice per workflow step.

  • Static context: always needed - system instructions, tool definitions, constraints
  • Dynamic context: selected per step - current state, relevant evidence, recent results
  • Retrieved context: fetched on demand when needed - repository files, documentation, logs

Static context is cheap because it's predictable. Retrieved context costs latency but saves budget when it's not needed. The worst option is including everything by default and hoping the model sorts it out.

Concrete Artemis connection

Repository and tool evidence are selected for the current task. The system doesn't include everything it knows - it includes what's relevant to this step. Evidence retrieval is a deliberate operation, not a context dump.
04

Memory patterns

Different kinds of information persist differently. Treating all memory the same is a common architectural mistake.

  • Conversation history: what happened in this session. Grows linearly, needs summarisation or windowing
  • Working memory: current task state, intermediate results. Scoped to the active workflow
  • Long-term memory: persistent knowledge across sessions. Retrieval-based, not context-stuffed

The distinction matters because each has different freshness, relevance, and cost characteristics. Conversation history gets stale. Working memory is immediately relevant. Long-term memory needs retrieval to avoid bloating every request.

Concrete Artemis connection

Workflow state is durable and explicit, not stuffed into conversation history. The system knows what step it's on without re-reading the entire conversation. State is structured data with defined transitions, not a narrative buried in chat messages.
05

Context window vs selective context

Large context window

"We can fit everything"
Higher cost, more latency, attention dilution, model must determine relevance itself.

Selective context

"We choose what matters"
Lower cost, faster, model focuses on relevant evidence, engineering effort to design selection.

The hardest context engineering problem is not fitting things in. It is knowing what to leave out.
